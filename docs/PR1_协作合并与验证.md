## 核心冲突处理

### 1. 迁移号碰撞

两边原来都使用了user_version 10—12，含义不同，不能直接保留任一方的版本判断。

| 统一版本 | 内容 |
|---|---|
| v10 | 原规划分支的单日例外、容量、依赖 |
| v11 | 原规划分支的统计账本、冻结基线 |
| v12 | 原规划分支的主动消息与提醒 |
| v13 | 学习资料、章节、考点、分析表（学习分支原v10） |
| v14 | study_pages、OCR作业和ocr_state（学习分支原v11） |
| v15 | 提问候选question_json（学习分支原v12） |

对于旧学习分支v10—v12，按实际study_documents存在且calendar_exceptions不存在识别，再补齐共享v10—v12，幂等补齐学习表和列。原规划分支按顺序新增v13—v15。升级前沿用数据库一致快照备份，形如plan.db.before-v15-时间.db；备份失败不继续升级。高于v15的库明确拒绝降级打开。

tests/fixtures保存双方真实旧迁移代码，验收对比旧表每个原字段、每行值，并覆盖双方10/11/12、重复执行和高版本拒绝。没有为旧数据伪造历史统计记录。

### 2. 手动排期不能绕过原有规则

手动候选计算释放当前任务自己可移动的旧块，仍读取课程、临时占用、当天窗口/容量和前置关系。锁定或已开始的旧块不能移动，未选择后续任务的既有安排也不能被破坏。

保存时创建受验证的预览，再走共享commit事务，复用版本/占用/依赖检查、统计账本和首次冻结；改期原因来自可信界面。跨查看窗口的旧块返回manual.previous供页面判断改期。批量课表导入同样检查已有计划，冲突时拒绝整次写入。

### 3. OCR与普通规划模型分开

设置新增可选“扫描件识别模型”，落库ocr_model；留空兼容沿用aiModel。主规划模型保持独立，不因OCR改写。OCR作业记录与实际请求使用同一份模型设置快照。

本次真实扫描页验证使用qwen3-vl-plus，普通规划用qwen-plus；均通过用户本机已配置接口。视觉兼容接口参考[阿里云官方文档](https://www.alibabacloud.com/help/en/model-studio/qwen-vl-compatible-with-openai)。同一接口/密钥是否开通所选视觉模型仍由其账户配置决定。

按真实页段返回readablePageRanges，部分识别不再宣称“前N页已读”；续传从firstMissingPage开始。来源包含文档ID、内容hash和页码。请求前后检查文件指纹；识别期间源文件改变后，旧结果不能覆盖重新解析的新正文。

### 4. 前后台共享运行循环

保留前台驱动时中断后台的协调机制。单轮最多8次决策、16次工具调用，总Run最多40次决策、上下文序列化上限60000字符、一次驱动240秒。新增轮次收尾、候选答复与批量草案仍走原确认链路，不能把“提出方案”说成“已保存”。
