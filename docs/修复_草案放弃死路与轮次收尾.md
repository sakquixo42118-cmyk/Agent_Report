# 修复：放弃草案后无法再录入 + 轮次耗尽只留报错

> 触发场景：用户在「下个月30号数学期末考」这条对话里先放弃了一版复习草案，随后又说
> 「根据教材分析知识点并生成合理的复习计划」。界面出现 8 条「查看工具执行记录」，
> 最后只剩一条「本轮已完成8次模型决策，达到上限」。没有任何结论，也没有新草案。

## 1. 真实原因（从 `%APPDATA%/suishou-plan-agent/plan.db` 的 `agent_events` 复盘）

那段运行 `bb0022d6-…`（scene=capture，turns=14）的实际工具序列：

| 轮次 | 调用 | 结果 |
|---|---|---|
| 1 | `get_study_documents` | 331 页教材，仅前 30 页有文字 |
| 2–4 | `read_study_pages` 1–13 | 读到封面与目录 |
| 5 | `create_task_drafts`（7 章计划） | **`此草案已提交或放弃，请新建录入。`** |
| 6 | `create_task_drafts`（同一份，原样重试） | 同上 |
| 7 | `get_task_draft` | 返回 `state=discarded` 的旧草案 |
| 8 | `create_task_draft` | 同上，仍被拒 |

根因不在读取教材，而在草案状态机：

- `task_drafts.run_id` 是 **`NOT NULL UNIQUE`**（迁移 v9），一个对话只有一份草案；
- 用户点了「放弃」→ `state='discarded'`；
- `ensureDraft()` 只要发现已有草案就直接返回它，`update()` 又因 `state!=='editing'` 抛
  「此草案已提交或放弃，请新建录入」；
- 模型没有别的入口可以新建草案，只能原样重试 → 8 轮预算烧完。

结论：**「放弃」把整个对话变成了死路**，模型越勤奋越糟。

## 2. 修复

### 2.1 放弃后可以重新开始（`src/main/drafts/service.ts`）

- 新增 `reopen()`：把 `discarded` 的草案清空条目（`items_json='[]'`、`created_ids_json='[]'`）、
  回到 `editing`、版本 +1，并写一条 `actor='reopen'` 的修订记录；
- `ensureDraft()` 分三种状态处理：`committed` → 明确提示「继续添加事项请新建对话」，
  `discarded` → `reopen`，`editing` → 原样返回；
- `update()` 的报错拆成两句：已确认创建的草案说清替代路径，已放弃的说清先加条目。

清空条目而不是保留，是因为「放弃」表达的就是不要那一版；原文仍保留在 `task_sources` 与修订历史里。

### 2.2 轮次用完前强制收尾（`src/main/agent/runner.ts`）

- 第 6 轮插入提示「只剩 3 次模型决策，先完成最重要的一步，不要继续逐页读取」；
- 第 8 轮（最后一轮）以 `forceResponse` 调用模型，工具表只保留 `respond`，逼出结论；
- 已经要求过收尾、模型仍只给纯文字时，**按其内容作为本轮答复结束**（此前会整轮判失败）；
- 预算提示只对当次请求有效，请求返回后从消息里移除，避免下一轮误以为预算仍然用完；
- 兜底报错改为「本轮已用完8次模型决策预算，已停止并保留记录。可以发送『继续』接着处理，或缩小目标」；
- `MAX_TURNS` 24 → 40：一轮失败的 8 次不该把后续正常追问一起判成超预算。

### 2.3 界面不再刷屏（`src/renderer/src/lib/chatEvents.ts` + `AgentChat.vue`）

连续的工具事件合并成一条折叠记录，摘要显示次数与工具名
（如「查看工具执行记录（8 次：read_study_pages、create_task_drafts）」），
中间夹着的助理/用户消息照常分行。抽成纯函数便于单测。

### 2.4 录入场景也带教材分析准则（`src/main/agent/bootstrap.ts`）

原先只有 `planning` 场景的系统提示含「先读目录页、按章分段读、整份计划用
`create_task_drafts` 一次提交」。用户是在 `capture` 场景里提的教材需求，现在抽成
`studyGuidance` 同时拼进两个场景，避免在录入场景里逐条 `create_task_draft` 把轮次烧光。

## 3. 验证

- `npm run typecheck` ✓ / `npm run build` ✓ / `npm test` **116 passed**（原 112 + 新 4）
- 新增用例：
  - `连续工具记录合并成一条，答复不被工具流水挤出视野`
  - `轮次用完前强制收尾，模型只给文字时按答复结束并保留记录`
  - `放弃后再录入重新开始，而不是卡在"已放弃"`
  - `同一对话里放弃草案后，模型能重新提交整份计划`
- 真实数据回放：把 `plan.db` 复制到临时目录，对那条 failed 运行重放
  「继续整理教材计划」，结果 `failed → awaiting_confirmation`，草案
  `discarded(2) → reopen(3) → editing(4)`，只用 2 轮而不是 8 轮。
  副本验证，未改动用户正式库。
