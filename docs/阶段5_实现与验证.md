# 阶段5：单日约束与依赖调度

版本：0.2.0-alpha.5；分支：feature/planning-agent；日期：2026-11-09。基于阶段4提交9a3554b继续实现。main仍是0.1基线，作业助手继续复用共享场景接口。

## 1. 这轮完成什么

- 日程增加单日停课、补课、临时占用。停课只取消指定日期的常规课程；不删除整周课表。补课按真实起止时间占用，原课需要另行添加停课记录。
- 今日和日程均可保存指定日期的正常/轻量状态、任务容量和可安排窗口。只影响该日，其他日期仍使用各自设置。
- 日程可明确指定任务前置关系；拒绝自身依赖和多级环。试排按拓扑就绪顺序安排，前置结束后再开始后续，保留任务间休息。
- 只选后续任务时，前置须已完成或有有效执行块；过去的计划块不能当作已完成证据。前置排不下，下游返回阻塞说明。
- 重排受未选择的后续计划约束；不擅自把后续任务一起移走。提交时重新独立检查依赖、容量、课表和时间约束。
- 今日Agent的get_calendar/get_free_slots/preview_plan和任务查询读取并应用这些约束。配置修改目前通过用户界面完成，不提供模型直接修改约束的工具。

## 2. 使用入口

更新后构建并正常重开应用，侧栏版本显示“v0.2 α5 · 约束调度”。

1. 在“今日→调整今日状态与容量”设置今天最多安排多少分钟；在日程的同类表单中可选择其他日期。
2. 在“日程→单日设置、临时日程与前置任务”添加日期例外。停课需选择当天真实存在的常规课程，补课需选择课程及新时段；临时占用只需名称、日期与时段。
3. 在“任务前置关系”选择后续任务与先完成的任务。它与0.1项目链条显示顺序是不同数据，不从链条顺序自动推断依赖。
4. 在日程勾选前后两项试排，或在今日对话要求模型实际试排。预览展示时间与未安排原因，确认后才保存执行块。

若新占用/恢复常规课/缩小容量与现有安排冲突，保存会被拒绝。先在日程调整或移除相关执行块，再保存设置；当前没有“把冲突设置与多项重排一次原子提交”的操作。调课的停课和补课分别保存，需核对两条结果。

## 3. 算法与数据

### 单日配置

`effectiveDaySettings = 单日非空字段覆盖全局默认`。单日窗口是硬约束，可明确覆盖当天起止；不是“偏好时间段”的软评分。轻量默认上限为全局每日上限的一半、向下对齐15分钟、最低15分钟；有自定义容量时优先使用自定义值（0表示休息日）。最终容量不超过当天窗口长度。窗口/容量修改仅影响目标日期，不自动挪动已有计划。

### 日历展开

先展开常规周课表，按课程ID＋日期排除停课实例，再加入补课和临时占用，得到实际固定占用。从每天有效窗口中减去这些占用及已安排任务的休息间隔。课程/占用不取整；任务起点与预留耗时向上对齐15分钟。

### 显式依赖

添加`后续任务→前置任务`时，从前置沿已有依赖遍历；能回到后续则拒绝成环。就绪任务按截止、现有优先级分数、任务ID确定顺序。待排任务只有在同批前置已安排、外部前置有可用执行块，或前置已完成时才可排；下界为当前时间与所有未完成前置结束时间的最大值。

已保存且本次不移动的后续块会给前置任务设置结束上界。部分失败重排仍保留原块并重算；提交前使用最终新旧块组合验证依赖，不只相信预览生成逻辑。删除仍被引用的前置任务、移除必要前置执行块或撤销会破坏后续计划的完成状态时，给出错误并保留原状态。用户可先移除相应依赖或调整后续计划。

这仍是确定性的拓扑就绪＋最早可行连续块算法。未实现完整算法C的偏好/负载/碎片/扰动加权搜索，也未实现自动拆分长任务、多块计划和自动扩大后继重排范围。手动分成多个普通任务后可显式建立依赖。

### 持久化与版本

迁移v10新增calendar_exceptions、day_overrides、task_dependencies，沿用迁移前一致性备份。输入、删除、审计记录在事务内；审计失败会回滚。新增配置IPC要求展示快照版本，过期页面不能覆盖新设置。预览版本包含例外、单日设置和依赖及状态，改变后必须重新试排。

共享PlanningSnapshot新增exceptions/dayOverrides/dependencies/effectiveDays；Occupancy新增busy并可带courseId。草案/复习桥接v1保持兼容；从旧开发提交接入时需一并更新共享类型和迁移总入口。

新增window.api：calendarExceptionSave/Delete、dayOverrideSave/Delete、dependencySave/Delete；最后一参均为PlanningSnapshot.version。业务函数位于main/planning/service.ts，纯计算位于engine.ts，依赖状态检查与读取位于constraints.ts。模型没有任意SQL、配置写入或用户确认权限。
