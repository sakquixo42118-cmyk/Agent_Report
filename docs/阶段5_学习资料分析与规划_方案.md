### 2.3 依赖与加载方式（已实测，非推测）

在 **Electron 33.4.11 / Node 20.18.3** 下用最小 PDF 验证：

| 尝试 | 结果 |
|---|---|
| `require('pdfjs-dist/legacy/build/pdf.mjs')` | `ERR_REQUIRE_ESM` —— 主进程是 CJS 输出且该包纯 ESM |
| `await import('pdfjs-dist/legacy/build/pdf.mjs')` | 成功，`numPages=1`，文本正确 |
| `item.transform` | 字号 24.0、y=720.0 可读 → **目录识别所需的字号/坐标成立** |

**实现约定**：
- 主进程用 `await import(...)` 动态加载，**不 require**；
- `getDocument` 传 `standardFontDataUrl`（指向 `pdfjs-dist/standard_fonts/`）与 `cMaps`，消除 `UnknownErrorException` 警告；
- 生命周期由 `loadingTask` 管理，`finally` 里 `destroy()`；
- `electron.vite.config.ts` 维持 `externalizeDepsPlugin()`，靠动态 import 在运行时从 `node_modules` 解析；打包进 asar 后验证一次（M1 收尾项）。

## 3. 总体架构

```
[对话输入区] 点击「教材/试卷」 → dialog(主进程) → 登记 study_documents(path + hash)
        ↓
[extract.ts] 按扩展名选解析器 → WordDoc{pages:[{page,text,lines:[{text,size,y}]}]}
        ↓
[outline.ts] 启发式识别章节（零模型成本） → study_chapters(带 confidence)
        ↓
[对话] 助理汇报「识别到 6 章，预计 6 次分析」 → 用户口头修正（"第3章跳过"）
        ↓
[访谈] 助理问考试日 / 每日投入 / 基础 / 目标 → study_goals + memory_facts
        ↓
[analyze.ts] 逐章串行调模型（每次 1 章，需 study_analysis 确认）→ 校验去重 → study_topics
        ↓
[plan.ts] 考点 → DraftItem(windowStart/End 按章分段) → 现有草案确认 → preview → commit
```

**架构原则**：不做独立资料管理界面；所有交互在现有对话流里，结果复用现有 `TaskDraftEditor` 与 `PlanPreviewCard`。

## 4. 数据模型（v10）

新增 6 张表，不改既有表（`LATEST_SCHEMA_VERSION = 10`）。风格沿用 `migrations.ts` 的 `db.transaction(() => { db.exec(...); db.pragma('user_version = 10') })()`。

```sql
-- 文档登记：过程输入，只存路径引用
CREATE TABLE study_documents (
  id TEXT PRIMARY KEY, path TEXT NOT NULL, name TEXT NOT NULL,
  ext TEXT NOT NULL CHECK(ext IN ('pdf','docx','txt','md')),
  size_bytes INTEGER NOT NULL, content_hash TEXT NOT NULL,
  page_count INTEGER NOT NULL DEFAULT 0, char_count INTEGER NOT NULL DEFAULT 0,
  status TEXT NOT NULL DEFAULT 'registered' CHECK(status IN ('registered','parsed','failed')),
  parser TEXT NOT NULL DEFAULT '', outline_confidence REAL NOT NULL DEFAULT 0,
  last_error TEXT, created_at TEXT NOT NULL, updated_at TEXT NOT NULL,
  UNIQUE(path, content_hash)
);

-- 章节：只作为分批单位，不是用户维护的资料目录
CREATE TABLE study_chapters (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  doc_id TEXT NOT NULL REFERENCES study_documents(id) ON DELETE CASCADE,
  ordinal INTEGER NOT NULL, level INTEGER NOT NULL DEFAULT 1 CHECK(level BETWEEN 1 AND 4),
  title TEXT NOT NULL, start_page INTEGER NOT NULL, end_page INTEGER NOT NULL,
  confidence REAL NOT NULL DEFAULT 0 CHECK(confidence BETWEEN 0 AND 1),
  selected INTEGER NOT NULL DEFAULT 1,           -- 由用户在对话中决定
  UNIQUE(doc_id, ordinal), CHECK(start_page >= 1 AND start_page <= end_page)
);

-- 学习目标：访谈产出的硬参数，程序用来算排期
CREATE TABLE study_goals (
  doc_id TEXT PRIMARY KEY REFERENCES study_documents(id) ON DELETE CASCADE,
  exam_date TEXT,                                 -- YYYY-MM-DD，访谈必问
  self_level TEXT CHECK(self_level IN ('weak','normal','strong')),
  target TEXT CHECK(target IN ('pass','good','excellent')),
  daily_min INTEGER CHECK(daily_min BETWEEN 15 AND 720),
  weekdays_json TEXT NOT NULL DEFAULT '[]',       -- [1,2,3,4,5]
  daypart TEXT CHECK(daypart IN ('morning','afternoon','evening','any')),
  assumptions_json TEXT NOT NULL DEFAULT '[]',    -- 哪些字段用了默认值，计划里要标注
  confirmed INTEGER NOT NULL DEFAULT 0,
  updated_at TEXT NOT NULL
);

-- 考点
CREATE TABLE study_topics (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  doc_id TEXT NOT NULL REFERENCES study_documents(id) ON DELETE CASCADE,
  chapter_id INTEGER NOT NULL REFERENCES study_chapters(id) ON DELETE CASCADE,
  ordinal INTEGER NOT NULL, name TEXT NOT NULL,
  importance INTEGER NOT NULL CHECK(importance BETWEEN 1 AND 5),
  difficulty INTEGER NOT NULL CHECK(difficulty BETWEEN 1 AND 5),
  exam_likelihood INTEGER NOT NULL CHECK(exam_likelihood BETWEEN 1 AND 5),
  estimate_min INTEGER NOT NULL CHECK(estimate_min BETWEEN 10 AND 480),
  evidence_page INTEGER, evidence_quote TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL, UNIQUE(chapter_id, ordinal)
);

-- 分析作业：可取消、可重入、可计费
CREATE TABLE study_analyses (
  id TEXT PRIMARY KEY,
  doc_id TEXT NOT NULL REFERENCES study_documents(id) ON DELETE CASCADE,
  chapter_ids_json TEXT NOT NULL, prompt_version TEXT NOT NULL, model TEXT NOT NULL,
  max_calls INTEGER NOT NULL, status TEXT NOT NULL DEFAULT 'running'
    CHECK(status IN ('running','done','partial','failed','cancelled')),
  error TEXT, created_at TEXT NOT NULL, finished_at TEXT
);

-- 逐次调用账本
CREATE TABLE study_analysis_calls (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  analysis_id TEXT NOT NULL REFERENCES study_analyses(id) ON DELETE CASCADE,
  chapter_id INTEGER NOT NULL, attempt INTEGER NOT NULL DEFAULT 1,
  status TEXT NOT NULL CHECK(status IN ('ok','invalid','error')),
  request_chars INTEGER NOT NULL DEFAULT 0, response_chars INTEGER NOT NULL DEFAULT 0,
  latency_ms INTEGER NOT NULL DEFAULT 0, error TEXT, created_at TEXT NOT NULL,
  UNIQUE(analysis_id, chapter_id, attempt)
);
```

**不新增"考点→任务"映射表**：`task_draft_links.source_ref` 存 `study:<docId>:<topicId>` 已足够溯源。

**画像职责划分**：能算进排期的硬参数进 `study_goals`；"函数部分很弱""喜欢先做题"这类软信息进 `memory_facts(scope='学习画像')`，由模型检索使用，不参与算术。

## 5. 学习画像访谈（替代表单）

助理在拿到章节后主动访谈。**不是问卷**：一次最多 2 个问题，最多 2 轮。

### 5.1 问题清单

| 优先级 | 问题 | 落点 | 缺失后果 |
|---|---|---|---|
| 必问 | 考试（或截止）是哪天？ | `exam_date` | 无法定计划终点，不出计划 |
| 必问 | 每天大概能投入多少时间？ | `daily_min` | 用全局 `dailyMaxMin` 并标注假设 |
| 必问 | 通常哪几天、哪个时段方便？ | `weekdays_json` / `daypart` | 默认每天、任意时段 |
| 影响权重 | 这门课你自认为基础如何：薄弱 / 一般 / 较好？ | `self_level` | 默认"一般" |
| 影响权重 | 目标是及格、中上还是冲刺高分？ | `target` | 默认"中上" |
| 可选 | 有没有已经掌握、可以跳过的章节？ | `chapters.selected` | 全部入选 |
| 可选 | 更想先通读教材，还是先做题再回头补？ | `memory_facts` | 不体现 |
| 可选 | 有没有特别的薄弱点？ | `memory_facts` | 不体现 |

### 5.2 访谈规则（写进场景 instructions）

1. 必问项缺失时**必须提问**，不得凭空假设日期。
2. 用户答"随便/不知道"→ 立即取默认值，写入 `assumptions_json`，并在计划里显式标注"按每天 4 小时、基础一般估算"。
3. 用户说"你看着办"→ 停止追问，用默认值出计划。
4. 不问与排期无关的信息（专业、学校、绩点）。
5. 已确认过的信息不重复问；用户改口则覆盖并记录。
6. 访谈与章节确认**合并在一轮回复里**完成，避免来回拉扯。

### 5.3 画像如何影响分析与排期

| 输入 | 影响 |
|---|---|
| `self_level=weak` | 提示词要求标出基础概念类考点；基础考点 `importance` 上调一档至多 |
| `target=pass` | 只保留 `importance ≥ 3` 或 `exam_likelihood ≥ 4` 的考点（覆盖率优先，不追求全覆盖） |
| `target=excellent` | 保留全部，含 `difficulty=5` 的拓展点 |
| `daily_min` | 覆盖本次计划的每日容量；不影响全局 `planning_settings` |
| `weekdays_json` | 章节窗口只落在这些星期 |
| `daypart` | 试排时传 `timeWindow`（现有 `preview` 已支持） |

## 6. 关键算法

### 6.1 文本抽取

- **PDF**：`await import('pdfjs-dist/legacy/build/pdf.mjs')`，逐页 `getTextContent()`，每 item 取 `str`、`transform`。按 y（容差 2px）聚行。**保留字号与 y**，否则无法识别目录。
- **DOCX**：`mammoth.extractRawText` 取正文；标题层级读 `word/document.xml` 的 `w:pStyle`/`w:outlineLvl`，缺失则正则兜底。
- **TXT/MD**：按行读，`#` 前缀作层级。
- **统一产物**：`{ pageCount, charCount, pages: [{ page, text, lines: [{ text, size, y }] }] }`。DOCX/TXT 无真实分页 → 按 2500 字符估页，`parser` 标记 `estimated-pages`，对话中说明"页码为估算"。
- **扫描件判定**：`charCount / pageCount < 40` → `status=failed`，提示"疑似扫描版，本期不支持 OCR"。绝不产出空考点。

### 6.2 目录识别（启发式，零成本）

1. 求正文字号中位数 `base`。
2. 候选行需：长度 ≤ 40、无句末标点，且满足其一 —— 匹配 `^(第[一二三四五六七八九十百千零\d]+[章节讲篇单元部分]|Chapter\s*\d+|\d+(\.\d+){0,2}\s*\S)`，或字号 ≥ `base × 1.15`。
3. `confidence` = 正则命中 0.5 + 字号突出 0.3 + 位于前 10% 页 0.2，截断 `[0,1]`。
4. `level`：字号聚类降序映射 1–4；同字号按编号深度（`1`→L1、`1.2`→L2）。
5. 区间：`start_page` = 标题所在页；`end_page` = 下一个同级或更高级标题所在页 − 1；末章到 `pageCount`。
6. **降级**：候选 < 2 → 每 20 页切一段，`confidence=0`，对话中明说"未识别到目录，已按页数等分，你可以说'第 2 段不要'"。
7. 用户在对话里的修正（跳过/合并）写 `selected`，重新解析不覆盖。

### 6.3 分章抽取

每章 1 次调用，串行。输入：章节标题 + 页范围 + 正文（截断 `MAX_CHAPTER_CHARS = 12000`，按段落边界，记录 `truncated`）。输出严格 JSON：

```json
{"topics":[{"name":"","importance":1,"difficulty":1,"examLikelihood":1,"estimateMin":45,"evidencePage":12,"evidenceQuote":"≤80字"}]}
```

校验链：`JSON.parse` 失败 → 追加"只输出 JSON"重试 1 次 → 仍失败该章 `invalid` 不阻塞其他 → 数值 clamp → `estimateMin` 向上对齐 15 分钟 → `evidencePage` 越界置 `null` → `evidenceQuote` 截 80 字 → 章内按名称相似度（>0.85）合并 → 单章最多 12 条，超出按 `importance+exam_likelihood` 截断。

预算：`maxCalls` 默认 20，用尽转 `partial`；`AbortController` 可取消，已成功章节保留。

### 6.4 考点 → 草案 → 排期

- 一考点一条 `DraftItem`：
  - `content`：`[第3章 极限] 洛必达法则的适用条件`
  - `estimateMin` 对齐 15 分钟，写入 `base_estimate_min`
  - `deadlineMode='set'`，`deadlineAt` = 考前一天 23:59
  - `windowStart/windowEnd` = 章节学习窗口
  - `origin='study'`，`category='学习'`
  - `note` 带上 `evidence_page`，便于回溯
- 窗口均分：可用天数 `D`、选中章节 `N`，第 `i` 章窗口 `[start+floor(i×D/N), start+floor((i+1)×D/N)−1]`，末章到考前一天。
- 顺序由窗口保证，不依赖任务依赖字段。
- 提交复用：草案确认（唯一创建）→ `planning.preview` → `commit`。
- `daysBetween` 限 7 天 → 跨周按周分片，对话中说明"本周先排前 2 章"。

## 7. 成本与安全

| 项 | 值 |
|---|---|
| 单章送入 | ≤ 12000 字符（约 6k–9k token） |
| 单次分析上限 | 20 次调用（硬上限） |
| 超时 | 120s（显式传参） |
| 重试 | 每章 ≤ 2 次，仅 JSON 失败时 |
| 真实测试 | 固定 2 次调用（3 页合成教材） |
| 记账 | `study_analysis_calls` 逐次记录 |

安全：
1. **路径只来自 dialog**，其余通道只收 `docId`；工具参数里**不存在路径字段**。
2. `fs.realpath` + 扩展名白名单 + ≤100MB + 常规文件校验。
3. 每次分析前重算 `content_hash`，不一致拒绝并提示重新选择。
4. 文件丢失 → 明确报"文件已不可访问：<path>"，不静默失败。
5. 送模型前剥离控制字符/零宽字符并截断。
6. **不把教材全文入库**，只存章节标题、考点名、≤80 字引文。
7. 模型输出全部校验后落库。
8. 分析花钱 → 必须先产生 `study_analysis` 待确认，写明"将分析 N 章、预计 N 次调用"。

**交付**：助理主动访谈 → `study_goals` 落库 → 确认后逐章抽取 → 考点入库 + 账本。

## 12. 风险

| 风险 | 应对 |
|---|---|
| pdfjs 动态 import 路径在 asar 内失效 | M1 收尾必须 `npm run build` 后实测；不行则把 `pdfjs-dist` 从 external 排除改为打包内联 |
| `standardFontDataUrl` 在 asar 内读不到 | 通过 `extraResources` 复制 `standard_fonts` 与 `cMaps`，运行时指向 `process.resourcesPath` |
| 目录识别不准 | 显示 `confidence`；对话里可跳过/合并；降级明确告知，不假装成功 |
| 扫描件误判 | `charCount/pageCount` 阈值 + 明确文案 |
| 模型输出污染 | 全字段 clamp + DB CHECK + 单测注入非法值 |
| 费用失控 | 20 次硬上限 + 逐次账本 + 确认前置 + 测试固定 2 次 |
| 访谈变成问卷 | instructions 限制"每次最多 2 问、最多 2 轮"，用户说"你看着办"即停 |
| `daysBetween` 限 7 天 | 跨周分片，对话说明 |
| 一考点一块排不下 | 通过更细的考点粒度控制单块时长；拆多块另立需求 |

**回滚**：v10 只新增表，停用 `study` 场景与按钮即可，表留着无害。
