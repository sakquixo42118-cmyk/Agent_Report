# 王浩宇模块：技术主线与答辩准备

对应0.2.0-alpha.7，日期2026-11-09。用于理解、交接和真实演示，不替代各阶段测试记录。孔传解释0.1基础，王浩宇解释共享规划Agent，罗德金接真实作业/OCR；实际代码与协作贡献按事实说明，可如实讲使用AI辅助实现与验证，避免声称每行代码均手写。

## 可以完整演示的闭环

自然语言输入→模型按需澄清/检索→可修订事项草案→确认唯一创建→读课表/临时占用/单日容量/依赖→算法试排→模型观察真实结果→计划卡确认→执行/完成→异步回顾→用户反馈→个人估时与统计→新事件触发主动检查。

另有模拟作业提供者：固定复习证据→同一草案入口→确认taskId→真实规划；明确标注模拟，不能当真实解题或OCR成果。

## 老师问“你具体实现了什么”

| 模块 | 能讲清的实现点 | 主要位置 |
|---|---|---|
| Harness | 原生tool_calls、执行后role:tool观察、暂停/恢复、预算、终态、场景白名单、可信确认 | main/agent |
| 输入与幂等 | 原文不可变、候选ID、版本快照、重复确认返回同一taskId、事务回滚 | main/drafts |
| 时间语义 | 截止是外部期限；执行块是准备何时做；改期不改截止 | shared/planning、main/planning |
| 约束算法 | 区间相减、15分钟对齐、当天容量、停补课、显式依赖拓扑就绪、前后置已有计划保护 | planning/engine、constraints |
| 个人校准 | 最近有效样本比例中位数，小样本收缩；原始值不重复乘系数，来源分桶 | main/memory |
| 后台状态机 | 完成先落库，后台可静默；租约/令牌、过期、对象静默、前台优先，消息不抢输入 | main/feedback、main/attention |
| 统计 | 事件账本、首次确认冻结分母、完成时截止快照、撤销修正、明确主动推迟才计数、误差按样本算 | main/statistics |

不要只说“优化了细节”：用一个明确失败、输入和修复解释。例如“原本改期会污染截止，现在分成两张业务数据；预览和确认分别校验，截止保持不变”，或“移除任务不能让完成率变高，冻结分母不跟着删”。

## Agent、Workflow和原创的关系

0.1“文本→模型一次提参数→程序分配”主要是固定工作流。新版模型可选工具，读取执行反馈后再决定澄清、检索、修改草案、试排、扩大窗口、请求取舍或结束；后台也可决定静默。这些选择不是所有请求固定走一条问卷。

Harness是让模型可靠行动的整个执行环境：工具、状态、上下文、权限、确认、预算、错误反馈、持久化与恢复，不只是一份函数清单。内部函数调用已满足本地项目需要，不必因为叫Agent就引入MCP。

原创不要求重造基础模型。确定性区间/依赖调度、个人校准、统计口径和队列状态控制都是自己的工程/算法内容，模型把它们当工具使用。当前最早可行排班不是全局最优，不能拿完整目标方案中的综合cost公式当已实现算法。

## SQLite、工具和事务怎么连

页面→preload有限接口→主进程服务→DAO/SQLite；模型只能请求已注册的业务工具。工具做参数/归属/版本校验，返回真实结果。正式写入需可信UI确认；模型没有“确认自己”或任意SQL工具。

网络在事务外。比如主动消息转草案，先用短事务同时建Run、保留来源并关联消息；提交后才发起模型。确认计划时，执行块、事件、基线与幂等结果一起成功或回滚。

## 排班算法最小口述

1. 展开每天真实课表，应用日期例外，加上其他执行块与休息占用。
2. 用区间相减得到空闲段，应用用户指定窗口和当天容量。
3. 依赖图先查环，进入拓扑就绪集合；就绪任务按截止、优先级、ID确定顺序。
4. 为当前任务找连续可行块，满足前置结束下界与截止/已存后续计划上界；任务时长向上对齐15分钟。
5. 放不下就返回连续空档/容量/依赖阻塞原因；失败重排保留旧块。确认前重查版本和独立约束。

有空闲总量不等于有足够连续空档；这是长任务试排失败时很值得展示的区别。

## 统计数字怎么对账

展示一个手算例子：首次计划3项，完成1项，移出1项，归档1项，后来另加完成1项。基线完成率仍1/3，近7日完成2项，后加1项单列，不能说2/2。

两个原始估时60和30分钟，实际90和30分钟，MAPE=(50%+0%)/2=25%，平均绝对分钟误差=(30+0)/2=15分钟。样本缺耗时/中断/范围变化时不参与。界面合成验收即使用此例，不作为真实用户提升率。

## 主动检查为什么不会每次打开都花API

先有新事件，再过开关、安静时段、间隔、每日额度、去重和后台席位。模型可以get_attention_context、按需search_memory，再选择silent/ask/suggest。结果返回前重查，用户完成或课程取消就作废。定时提醒是独立规则，不调用模型。

“课表已结束”不证明到课，“尚未标记完成”不证明用户没做。适度提醒是提供核对/调整入口，不给人贴拖延标签。系统通知是可选批次，主记录始终在今日。

## 建议当面操作的验收顺序

1. 明确事项直接草案；模糊事项按需追问，回答后恢复同一Run。
2. 设置课表和临时占用；同时排有依赖的两项，看实际工具记录和确认卡。
3. 放一个连续时段不足的长任务，看算法失败原因，而非模型口头猜测。
4. 完成任务，说明提交不等模型；后台可提问也可静默，用户可忽略。
5. 在统计页对账基线、主动推迟与样本误差；说明旧历史不补造。
6. 主动消息转事项/讨论调整，检查同一来源和Run，确认前没有正式写入。

真实模型行为有变化，演示前在独立演示库跑一遍，保留一份明确标记为合成/回放的备用材料。测试通过数表示覆盖范围，不是原创程度、需求完成率或模型准确率。
