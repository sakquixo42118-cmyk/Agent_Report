# 阶段7：主动检查、适度催办与运行期间提醒

版本：0.2.0-alpha.7；日期：2026-11-09；分支：feature/planning-agent；基于88c061c继续。此轮完成上次列出的三项主动交互收尾功能，保留既有完成回顾、草案、约束排班和统计。

## 1. 使用方式

今日新增“今日消息”：课后询问、任务风险建议、执行开始和截止提醒都保存在这里。侧栏今日红点合并有效未读消息数，完成回顾仍有自己的回复表单。新消息不自动打开对话，不弹窗，不清空正在编辑的输入。

- 课后消息可选“没有新增事项”，或输入作业/待办交给助理整理为草案；确认前不创建正式任务。课表结束只是一条时间证据，不代表用户到课或老师确实布置了作业。
- 任务消息可“核对状态 / 讨论调整”：新规划Run先读取真实任务，必要时试排并确认。后台不会自动调级、改期或写长期记忆。
- 稍后可选15/60/120分钟，必须早于消息过期；恢复同一消息，不重新调用模型。忽略只处理本条。停止对象提醒会持久化，任务的自动完成回顾也遵守它；手动反馈仍可用。
- 设置中的“主动消息与时间提醒”可调开关、安静时段、检查间隔/额度、提前提醒时间与对象恢复。恢复只处理后续新事件，不重放已处理实例。
- 默认安静时段22:00—08:00，暂停新的模型后台工作和时间提醒。模型主动检查默认至少间隔60分钟、每天最多3次尝试/3条消息；完成回顾另有原配额，两者共用一个后台模型席位。
- 时间提醒默认在今日保存，不需要模型。可选提交Windows系统通知，默认关闭；通知按批合并、至少间隔5分钟，每日最多6批。只有用户点击通知时才显示窗口并定位今日消息。

必须保持软件运行。关窗仍是正常退出，未增加托盘或自启动；不宣称退出、关机时仍能提醒。下次运行/休眠恢复时，只核对近期遗漏，不补一周的课后问题。

## 2. 哪些规则由程序做，哪些由模型做

| 环节 | 程序负责 | 模型负责 |
|---|---|---|
| 候选生成 | 展开有效课表，应用停补课，发现新结束实例；读取未标记完成的风险事项 | 不虚构课程、任务或截止 |
| 是否调用 | 新证据、开关、安静时段、间隔、配额、去重、后台席位 | 未获得运行机会时不调用模型 |
| 本次行动循环 | 执行get_attention_context、search_memory，返回真实证据 | 按需检索记忆，自主选择silent、ask或suggest |
| 发布 | 检查证据版本、令牌、租约、设置及当前状态，写一条站内消息 | 给完整简短问题/建议，引用实际eventKeys |
| 时间提醒 | 按已确认执行块/截止与提前量计算、去重 | 不参与定时计算，不消耗检查模型预算 |
| 后续操作 | 关联同一Run、持久化原文、事务和幂等 | 用户主动进入后，使用现有规划/录入工具决策 |

这不是“每次打开→固定问一句”。重复激活只唤醒轻量扫描；没有新证据或处于冷却/安静时段时不发起模型请求。新证据也不保证会有消息，silent是正常终态。规则给模型有限事实与可执行工具，模型决定是否有值得问的信息。

## 3. 证据、队列与去重

课后候选只包含最近3小时内、且在此功能启用之后结束的真实课程/补课实例；停课与旧实例不进入。风险候选来自确认截止前24小时/后6小时内，或最近2小时结束但仍未标记完成的执行块。事实描述为“未标记完成”，不推断用户实际没做。

课程实例键含课程ID、真实起止；同实例检查完或忽略后不反复询问。风险实例按任务ID＋本地日期去重。一次检查合并同类最多3个证据，发布最多一条消息。证据变化时使在途旧结果失效，未发布的有效证据可重新排队；已经处理的实例不重放。

任务时段提醒键为taskId＋start；只变结束时间则更新原消息事实，不新发同一开始提醒。截止提醒键为taskId＋已确认截止。重评/修改评分不会重发；改变目标时间会取消旧消息，按新目标重新判断。旧due_notified或snooze_count不作为新去重事实。

开始提醒默认提前10分钟，截止提前量沿用用户设置（默认24小时）。恢复后，未确认完成的开始安排最多追溯结束后12小时，截止最多追溯24小时；超过范围标为过期，不无限补发。单日时间提醒默认最多12条，可配置，和主动消息额度独立。安静时段结束后扫描仍在有效期内的事件，系统通知只提交一批摘要。

队列每个工作有令牌和120秒租约，4轮模型决策/8次工具调用/70秒总超时，失败最多2次自动尝试。每日额度按检查尝试计，失败/已发起后被打断的尝试也计入；手动重试不会清空日额度。失败不产生错误红点，不撤销完成，也不改动任务。

用户前台对话开始时会中断后台请求；两类后台工作不会并行占用模型。网络在数据库事务外。应用退出时中断请求、释放租约，迟到结果不能发布。单实例锁避免同一数据目录重复启动两套定时器；领取检查时还在事务内复查配额/间隔与有效租约。安静时段也应用到原完成回顾；完成事务仍立即提交，不等待模型。

## 4. 技术接口与数据

迁移v12增加attention_settings/state/events/jobs/attempts/messages/mutes/desktop_batches；既有数据与统计账本不搬迁，沿用迁移前一致性备份。

- main/attention/preferences.ts：版本化设置、跨午夜安静时段、对象静默。
- main/attention/service.ts：证据、扫描、队列、重查/发布、消息状态、提醒和通知批次日志。
- main/attention/worker.ts：受控工具循环、失败/恢复、后台调度；没有任务写工具。
- main/agent/background.ts：共用后台席位及前台优先中断。
- main/attention/bridge.ts：在可信事务内准备消息关联Run；提交后才启动模型。
- main/attention/desktop.ts：可选Windows通知适配器；站内消息是主要记录。通知提交/展示/失败分别记日志，提交不代表用户一定看见。
- attentionState/Settings/Action/Unmute/Check/Capture/Discuss与两个订阅接口由preload暴露；不开放SQL、任意场景名或任意文件路径。

消息有open/snoozed/answered/dismissed/cancelled/expired状态。已读不等于已答；过期、已完成、改期、停课或对象静默会消除有效红点。原文、证据引用和关联Run保留，消息双击不创建两个Run。创建Run或来源关联失败时一起回滚，后台网络不进入这个事务。

get_attention_context额外返回本地可读时间及timeZone，避免把UTC截止误读成本地时间。只保留简短行动记录、来源与决策，不保存模型内部思维链。
