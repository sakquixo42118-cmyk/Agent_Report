# 共享场景与复习任务接入契约 v1

对应版本：0.2.0-alpha.4—alpha.5；协议常量：`SCENE_CONTRACT_VERSION = '1.0'`。代码以本仓库 `feature/planning-agent` 为准。本协议是进程内 TypeScript 模块接口，不需要 MCP，也不是动态安装的插件系统。

阶段5兼容补充（2026-11-09）：数据库当前v10；PlanningSnapshot新增exceptions/dayOverrides/dependencies/effectiveDays，Occupancy新增busy。preview_plan与确认提交自动遵守这些约束。依赖通过日程显式录入，复习草案不会自行推断或写入依赖；可先确认建任务，再由用户设置先后关系。新增配置IPC使用展示快照version，详见[阶段5记录](阶段5_实现与验证.md)。作业模块应以当前共享提交为基础，不能占用已使用的迁移编号。

## 1. 共用什么

罗德金的作业模块复用同一套模型客户端、运行循环、Run/事件、确认机制、任务草案、任务数据库和规划服务。不要另建一套模型循环或复制任务表。作业题目、知识卡、OCR稿及其修订记录属于作业模块自己的领域数据；数据库迁移编号由共享入口统一分配。

真实路径：

```text
作业页面 → 有限的 preload/IPC → 作业服务/已注册场景
→ LLM选择本场景允许的工具 → 参数验证 → 领域服务 → 结构化观察
→ 继续决策 / 等待回答 / 等待确认 / 结束

作业模块的复习建议＋证据 → TaskDraft
→ 用户核对和修改 → 可信确认 → 唯一创建taskId
→ 规划Run读取这些taskId → preview_plan → 用户确认 → 执行块
```

模型选择是否澄清、读取哪些相关信息和使用哪个工具；算法负责排班、版本校验和事务。模型没有任意 SQL、文件路径或用户确认工具。

## 3. 注册工具和场景

顺序：注册工具与确认处理器 → 注册场景 → 启动Run。重复工具/场景名、未知工具、未知确认类型会在注册时拒绝。

最小只读模块示例（在主进程启动模块中执行一次）：

```ts
import { registerTool, registerScene } from './agent/registry'
import { startSceneRun } from './agent/runner'

registerTool({
  effect: 'read',
  definition: { type: 'function', function: {
    name: 'get_study_example', description: '读取明确标注的测试题证据',
    parameters: { type: 'object', properties: {}, additionalProperties: false }
  } },
  execute: () => ({ ok: true,
    data: { text: '固定测试数据：交换行后需要变号。', simulated: true },
    sourceRefs: ['fixture:determinant:v1'], stateVersion: 1 })
})
registerScene({
  id: 'study', title: '作业帮助',
  instructions: '按需读取题目并解释；固定数据不能冒充模型批改。',
  tools: ['get_study_example', 'respond', 'ask_user', 'finish_reply'],
  confirmationKinds: []
})
// 由可信IPC处理器在用户启动该场景时调用；需先配置工具调用模型。
const run = startSceneRun('study', '请解释这道题的错误步骤')
```

真实实现应按题目ID读取自己已保存的数据并检查存在性/版本，而非接受任意本机路径。当前 `execute` 和 `getProposal` 为同步接口：异步OCR/联网导入要先完成、保存成记录，再由工具读取；不要直接返回 Promise 冒充 ToolResult。需要异步工具时先共同升级注册表与执行循环。

运行时JSON Schema仅实现本仓库所需子集：object/array/string/integer/number/boolean/null、类型数组、required、enum、上下限、长度、items、uniqueItems；对象必须 `additionalProperties:false`。不支持 `$ref`、oneOf、pattern、format等，不支持的键注册时拒绝。语义约束仍需领域服务验证。

## 4. 观察、暂停和确认

```ts
interface ToolContext { observed: Map<number, string>; runId?: string }
interface ToolResult {
  ok: boolean; data?: unknown; errorCode?: string; message?: string;
  sourceRefs?: string[]; stateVersion?: string | number;
  pause?: 'waiting_user' | 'awaiting_confirmation' | 'completed';
  pending?: PendingChange;
}
```

`observed` 是当前决策轮的任务读取版本凭据，不是跨场景通用授权。草案工具直接用 `runId` 检查归属；不能把另一Run的draftId拿来修改。

工具执行后，`pause/pending` 由运行器消费，剩余字段作为 `role:tool` 观察返回模型，并写事件。只需要回答时用 `respond(mode='answer',text)`；需要信息时用 `ask_user(question)` 或 `respond(mode='question',text)`。普通文字输出会被要求纠正为结构化终态。

现有确认类型：priority（旧结构无type字段）、plan、memory、task_draft。新增确认种类需要同步修改共享 `PendingChange` 联合类型、注册主进程确认处理器并增加对应UI。注册表不会自动生成新确认卡；每个处理器自己承担身份/版本/事务/幂等校验。不要把 `commit_*` 或 `confirmed:true` 暴露成模型可调用的写入授权。

Run状态：running → waiting_user / awaiting_confirmation / completed / failed / cancelled。回答通过 `sendMessage` 恢复同一Run。task_draft等待确认时也允许继续对话修订；其他待确认操作先确认或放弃。每轮最多8次模型决策、16次工具调用，整个Run最多24次模型决策，每次驱动超时120秒；失败保留记录，不能假称已经保存。

## 5. 草案字段与生命周期

`TaskDraft` 含 id/runId/version/state/sourceKind/sourceText/sourceRef/items/createdTaskIds/updatedAt；state为editing、committed或discarded。

| DraftItem字段 | 约定 |
|---|---|
| id、origin | 候选身份由服务生成；来源model/user/import/review，不可由模型伪造 |
| content | 1—500字 |
| estimateMin、estimateGroup | 原始分钟5—1440或null；分组原文1—60字；建议值需note标明 |
| importance、urgency、category | 各1—5；分类工作/生活/学习/其他 |
| deadlineMode、deadlineAt | unknown/none/set；只有set保存真实ISO时间；none不表示“当天截止” |
| windowStart、windowEnd | 可空的YYYY-MM-DD执行范围，独立于截止 |
| included、note | 纳入开关、建议依据/修订说明 |

五个模型工具：get_input_source、create_task_draft（增加候选）、get_task_draft、update_task_draft（draftId+expectedVersion+itemId+patch）、propose_task_draft（生成待确认卡）。没有模型提交正式任务工具。

修改、保存、确认绑定版本。数据库保留输入原文和各版本条目快照；补充回答另存在Run消息/事件中。用户手动编辑需点“保存草案修改”，保存前不让当前聊天继续使用旧内容，也不允许确认。尚未保存到服务端的输入不保证退出后恢复。

确认仅创建included项，耗时未知时拒绝创建；截止unknown可保留但后续试排会要求确认。正式任务记录 `ai_status=confirmed`，人工锁定评分和已确认参数，不再被旧自动分析覆盖。确认不等于已经排班；执行块必须经过另一次预览与确认。相同draft/version重复确认返回相同taskId，事务失败时任务和来源链接一起回滚。

每Run一份草案，已提交草案不能原地变成另一批新任务；请新建录入。当前支持修订候选任务信息，**不提供任意现有任务字段修改工具**；现有任务调级/执行改期继续使用已有入口。

## 6. 作业模块最小桥接示例

先注册具有task_draft确认权限的 `study` 场景，再注册提供者：

```ts
import { registerReviewProvider, startReviewProposal }
  from './drafts/reviewBridge'
import { getRun } from './agent/store'

registerReviewProvider({
  id: 'study_reviews', simulated: false,
  getProposal: key => {
    // 实际改为读取作业模块的已保存记录；必须核对存在性和修订号。
    if (key !== 'review-example-v1') throw new Error('复习建议不存在')
    return { key, scene: 'study', title: '复习行列式换行变号',
      evidence: [{ id: 'study:answer-example:v1', title: '错误步骤',
        text: '保存并经核对的错误步骤摘要' }],
      items: [{ content: '重做原题并检查换行符号', estimateMin: 30,
        estimateGroup: '线性代数', category: '学习', deadlineMode: 'none',
        note: '30分钟为建议，等待核对' }] }
  }
})
// 在作业模块的有限IPC处理器内执行并返回AgentRun。
const runId = startReviewProposal('study_reviews', 'review-example-v1')
const run = getRun(runId)
```

此例的study场景需将五个草案工具加入tools，并将 `task_draft` 加入confirmationKinds。`simulated:false` 只标识提供者性质，不会把示例数据自动变成真实证据；真实来源由作业服务负责。证据ID/title/text均非空，ID唯一；每次1—60项/证据，整个来源JSON最多12000字。建议key最多100字，应用内具有稳定语义；同provider+key重复打开同一Run，新一次复习需求应使用新key（如包含复习轮次）。

内置 `mock_study / determinant-sign-v1 / study_mock` 是固定测试案例。界面明确标注模拟，没有真实解题、OCR或自动生成知识卡。

注册表只约束已配置场景的工具调用；新增模块代码本身拥有主进程权限，需要共同代码审查。不要将前端传入的任意provider/scene直接交给不受控的通用执行入口。

## 7. 已有前端API与对接顺序

| window.api | 返回 / 用途 |
|---|---|
| captureStart(goal) | AgentRun，自主录入 |
| batchPreview(raw) | AgentRun，人工预览无需模型；最多60非空行 |
| draftGet(id)、draftSave(id,version,items)、draftAdd(id,version,content) | TaskDraft |
| draftConfirm(id,version,accepted) | AgentRun，可信用户操作 |
| draftContinuePlan(id) | AgentRun，复用同一规划交接Run；最多20项一次试排 |
| mockReviewStart() | AgentRun，内置模拟桥接入口 |
| agentHistory()、agentGet(id)、agentSend(id,text)、agentCancel(id) | 历史最近30条/恢复/取消 |

现有 `agentConfirm(runId,true,version)` 确认事项草案时也必须传展示版本。旧 `taskBatchCreate` IPC已禁用，旧调用者要迁移到batchPreview，不得回退成直接建任务。

作业模块应新增自己有限的IPC来取得已保存建议，然后调用桥接；目前并没有通用 `studyStart` 或 `propose_review_tasks` preload API。UI可参考 `agentNavigation.ts` 中的 `openAgentRun(run.id)` 定位到今日会话；这是renderer内部导航函数，不是主进程导出。

## 8. 错误与验收

注册表错误：UNKNOWN_TOOL、TOOL_NOT_ALLOWED、INVALID_CONTEXT、INVALID_ARGUMENTS、TOOL_ERROR；读取尚无草案为NO_DRAFT。业务服务与IPC目前抛中文Error，**没有统一的领域错误码枚举**，页面需要展示错误并保留输入；不能假设存在DRAFT_CONFLICT等尚未实现的码。

联调前必测：未知/越权工具，伪造确认参数，错误来源/版本，重复模块key，重复确认，写入失败回滚，重启恢复，真实taskId进入试排，截止不变，以及完成回顾未读/忽略旧功能。固定替身测试和真实模型测试分别记录。不得用固定测试题宣称作业模型准确率或OCR识别率。
